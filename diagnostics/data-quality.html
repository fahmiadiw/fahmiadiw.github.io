Four error types do almost all the damage.

Name mismatches (23 villages), subtotal rows (5), mixed periods (66) and a duplicate name (2) leave 79 of 131 villages with a wrong population, and 4 of 13 puskesmas sit outside the regency.

The errors change the decision, not just the numbers.

The raw merge overstates population by 31% yet makes access look better (7.4% vs 10.1% beyond 5 km). It understates Bandung Baru's load nearly 3×, drops Rejosari from #4 to #9, pushes Wates up to #5 and deletes Puskesmas Adiluwih from the model.

Eight automated rules catch all of it, every cycle.

Rules R1–R8 run in Python on every data refresh. After cleaning: 0 unmatched villages, 0 facilities outside their boundary, and village totals reconcile to official sub-district totals within 0.02%.

I've cleaned hospital EMR and NGO field survey data by hand, and now build that work as rule-based pipelines in Python and SQL, so the same checks run every reporting cycle before anything reaches a dashboard. Here is the reproducible script and rule set; happy to walk through it in 15 minutes.
